## SUPERVISOR REVIEW — P05 RC02 DEFINITION

**DECISION: ACCEPT**

The readiness audit is sufficient to release RC02 implementation. It correctly separated product definition from implementation, identified the real legal/content blockers, avoided inventing corpus rights, and produced an implementation order that can advance in GitHub without depending on local Android access.

### Accepted product/UX decisions

- Preserve the four primary tabs: **Hoy / Explorar / Leer / Biblioteca**.
- **Calma viva v2** remains the visual direction: warm rose/mauve/peach/lavender family, light + dark, accessible contrast, no green-dominant identity.
- **Notes:** one local note/reflection per verse in v1; tap verse → contextual actions → add/view/edit/delete note; preserve existing save/unsave; add soft highlight support; expose Notes/Highlights in Biblioteca.
- **Spotify v1:** no player SDK. Use a secondary card in **Hoy** → music sub-screen → curated Christian categories/playlists → explicit **Abrir en Spotify** using verified external links/fallback. Spotify is optional and never required for Bible use.
- **Reminder v1:** opt-in, max once daily, configurable local time, best-effort Android notification. Accepted copy direction: **“Un momento para la Palabra”** / **“Tu lectura de hoy te espera. Léela a tu ritmo.”** Tap target: **Hoy / Palabra del día**. No exact-alarm promise.
- **Palabra del día:** curated positive/encouraging catalog with context CTA; selection deterministic by local date; this restriction applies only to the daily feature, not to the general Bible corpus.
- **Privacy:** notes remain local and there is no app-managed account/cloud sync. Implementation must audit Android backup behavior and prevent accidental cloud backup of note content where feasible/appropriate; do not claim “never leaves device” until effective manifest/backup behavior is verified.

### Bible/corpus decision

Target product remains:
- **Protestant:** Reina-Valera 1960.
- **Catholic:** a recognized complete Catholic edition.

However, **neither requested corpus is authorized for APK bundling today** based on the evidence in this audit.

Therefore:
- RVR1960 integration remains **BLOCKED on written redistribution rights + authorized digital corpus**.
- Catholic corpus integration remains **BLOCKED on exact-edition selection + written redistribution rights + authorized digital corpus**.
- Do not scrape/copy from Bible.com, BibleGateway, another app, purchased ebook, or other unauthorized source.
- RC02 engineering may continue using the existing RV1909 only as the current technical/runtime baseline.
- **Final RC02 product acceptance/release must not present Protestant/Catholic selection as complete unless both requested product paths are backed by real authorized corpora.**
- Build the multi-Bible/canon/availability architecture now so legal corpus delivery can be plugged in later without redesign.

For Catholic licensing research, prioritize **BIA (Biblia de la Iglesia en América)** and **Biblia Latinoamérica** as first contacts/candidates; Biblia de Jerusalén remains a strong alternative. This is a licensing/research priority, not authorization to ingest any text.

### Accepted implementation order

Authorize the audit’s reordering: establish translation/canon/reference foundations before note data is locked to the old single-translation model.

1. **Wave 1 — Calma viva + multi-Bible foundation**
   - visual system;
   - large-text shell;
   - translation/tradition/canon/availability models;
   - robust BibleReference;
   - non-destructive migration foundation;
   - preserve RV1909 behavior and frozen search/topic invariants.

2. **Wave 2 — Notes + highlights + Biblioteca**
   - true SQLite CRUD;
   - restart persistence;
   - per-translation references;
   - no cloud/account dependency.

3. **Wave 3 — Palabra del día**
   - deterministic local-date selection;
   - positive curated catalog;
   - real context navigation.

4. **Wave 4 — Local reminder**
   - verify Expo SDK 57-compatible notifications dependency before install;
   - permission/schedule/cancel/tap handling;
   - no exact-alarm semantics.

5. **Wave 5 — Spotify**
   - Hoy card + sub-screen;
   - verified HTTPS/deep links;
   - five initial categories;
   - no SDK/OAuth/player in v1.

6. **Wave 6 — Corpus/import infrastructure**
   - private/local importer;
   - rights/provenance/coverage/hash gates;
   - no copyrighted corpus in GitHub;
   - actual RVR1960/Catholic ingestion remains blocked until rights evidence exists.

7. **Wave 7 — Search v2**
   - translation-aware/index-aware;
   - preserve 100 topics, A–Z/free-form separation, whole-term and `amor`/ `llamó` regression;
   - personal-note search must remain distinct from Scripture results.

8. **Wave 8 — RC02 candidate**
   - only after source-level/integration gates pass;
   - one APK candidate unless a concrete Android-only defect requires an earlier diagnostic APK;
   - exact HEAD + CI runs + artifact + SHA256 + QA matrix;
   - final physical validation on Human phone.

### APK policy

Accepted. Do not build APKs for routine microchanges. Use tests/typecheck/Expo checks/Android export and repository review first. An APK is an evidence artifact for a mature candidate or for a specific runtime question that cannot be resolved otherwise.

### Remaining external blockers

The corpus licensing tasks do **not** block Waves 1–5 or the infrastructure portion of Wave 6. They block actual copyrighted corpus ingestion and final dual-tradition product acceptance.

P05 definition gate is complete.

Decision: **ACCEPT**.
